# HEXAGEN — Hexagonal to Spring Boot Model Transformation

This project transforms **HMM (Hexagonal Metamodel)** architecture models into **SMM (Spring Boot Metamodel)** code models using **Eclipse Epsilon** (ETL for transformation, EVL/EOL for validation).

## Metamodels

### HMM — Hexagonal Metamodel (`models/hmm.ecore`)

Defines the structure of a hexagonal architecture:

- **Hexagon** — root container with infrastructure, application, and domain layers
- **InfrastructureLayer** — ports (inbound/outbound) and adapters (inbound/outbound)
- **ApplicationLayer** — application services containing use cases with input/output DTOs
- **DomainCore** — aggregate roots (with members: entities, value objects, attributes), domain services, domain events, and domain relationships between aggregates
- **Links** — connections between layers: AdapterPortLink, ServicePortLink, ServiceAggregateLink, ExternalSystemLink, ServiceDomainServiceLink

### SMM — Spring Boot Metamodel (`models/smm.ecore`)

Defines the structure of a Spring Boot application:

- **Application** — root with name, basePackage, javaVersion, serverPort
- **Module** — grouping unit containing entities, value objects, repositories, services, controllers, DTOs
- **Entity** — JPA entity with attributes and idType
- **ValueObject** — immutable value class with attributes
- **Repository** — Spring Data repository with entityType and methods
- **Service** — business logic service with requiredRepositories and methods
- **Controller** — REST controller with basePath, service reference, and endpoints
- **Dto** — data transfer object with attributes

## Setup in Eclipse with Epsilon

### Prerequisites

1. **Eclipse Modeling Tools** (2023-12 or later) from https://eclipse.org/downloads/
2. **Epsilon 2.5+** — install from the Eclipse Marketplace (`Help → Eclipse Marketplace → search "Epsilon"`) or via the update site: `https://download.eclipse.org/epsilon/updates/`
3. **EMF (Eclipse Modeling Framework)** — included in Eclipse Modeling Tools by default

### Importing the Project

1. Open Eclipse
2. `File → Import → General → Existing Projects into Workspace`
3. Select root directory: the `hexagonal-validation` folder
4. Ensure `hexagonal-validation` is checked and click `Finish`

The project should appear in the Project Explorer with all models, transformations, tests, and launch configurations.

## Running the ETL Transformation (`trasformation/HMM2SMM.etl`)

The `trasformation/` folder contains the ETL transformation script that reads an HMM model and produces an SMM model.

### How the Transformation Works

The `HMM2SMM.etl` transformation:
1. Creates an `SMM!Application` from the `HMM!Hexagon` root
2. For each `AggregateRoot` in the domain: generates an `Entity` (with UUID id) and a `Repository`
3. For each `Entity` member inside aggregates: generates an `SMM!Entity`
4. For each `ValueObject` member inside aggregates: generates an `SMM!ValueObject`
5. For each `ApplicationService`: generates an `SMM!Service` with methods from use cases
6. For each `InboundAdapter`: generates an `SMM!Controller` with REST endpoints
7. For each `DomainEvent`: generates an `SMM!Dto`
8. Wires repositories to services, services to controllers

The alternative transformation at `models/transformation/Hexagonal2springboot.etl` follows a similar approach but uses module splitting per application service.

### Running the Transformation via Launch Config

1. Right-click `runconfigs/HMM2SMM.launch` → `Run As → Run Configurations`
2. Select `HMM2SMM` and click `Run`
3. The SMM output is written to `models/LibraryLoanSystem-smm-etl.xmi`

### Launch Configuration Details

The `HMM2SMM.launch` loads:
- **Input (HMM)**: `models/LibraryLoanSystem.xmi` (read-only)
- **Metamodel (HMM)**: `models/hmm.ecore`
- **Output (SMM)**: `models/LibraryLoanSystem-smm-etl.xmi` (written)
- **Metamodel (SMM)**: `models/smm.ecore`
- **Transformation source**: `trasformation/HMM2SMM.etl`

To transform a different domain, edit the launch config and change the `modelFile` entries for both HMM and SMM to point to the desired `.xmi` files.

## Running the Test Suite

### Individual Metrics

The `tests/metrics/` folder contains four quality metrics. Each can be run separately:

| Metric | File | Launch Config | What It Checks |
|---|---|---|---|
| SC | `sc.evl` | Syntactic Correctness | Well-formedness of SMM model (25 constraints) |
| AF | `af.eol` | Architectural Fidelity | HMM-to-SMM correspondence (5 rules) |
| FC | `fc.eol` | Functional Completeness | Element count ratio (generated vs expected) |
| SM | `sm.evl` | Structural Maintainability | Orphans, broken refs, duplicates |

### Aggregate Evaluation

The `evaluate-all.eol` script runs all four metrics in sequence and produces a unified score report:

1. Right-click `runconfigs/RunEvaluateAllEtl.launch` → `Run As → Run Configurations`
2. Click `Run`

Other launch configs evaluate different SMM variants:

| Launch Config | SMM Model Evaluated |
|---|---|
| `RunEvaluateAllEtl.launch` | `LibraryLoanSystem-smm-etl.xmi` |
| `RunEvaluateAllExpected.launch` | `LibraryLoanSystem-smm-expected.xmi` |
| `RunEvaluateAllHybrid.launch` | `LibraryLoanSystem-smm-hybrid.xmi` |
| `RunEvaluateAllPure.launch` | `LibraryLoanSystem-smm-pure.xmi` |

### Results

Results are printed to the Eclipse console. A sample report is documented in `report.md`.

## AI-Assisted Model Generation

The `trasformation/contextprompts/` folder contains domain specification prompts (.md files) used to generate SMM models via AI (Large Language Models).

### Generation Methods

**Pure AI**: The LLM receives only the domain prompt + `smm.ecore` + an example SMM and generates a complete `smm-pure.xmi`.

**Hybrid AI**: The LLM receives the actual HMM source model + `hmm.ecore` + `smm.ecore` + an example SMM and generates the `smm-hybrid.xmi`.

For detailed prompt instructions, see `trasformation/SETUP.md`.

## Adapting to a Different Domain

1. **Create the HMM model** — define aggregates, entities, value objects, application services, use cases, ports, adapters, and links in a new `.xmi` file conforming to `hmm.ecore`
2. **Create a domain prompt** — add a `.md` file in `trasformation/contextprompts/` describing the domain concepts
3. **Update launch configs** — point the HMM model entry to the new `.xmi` file
4. **Run the ETL transformation** — via `runconfigs/HMM2SMM.launch`
5. **Evaluate** — run the test suite against the generated SMM output
